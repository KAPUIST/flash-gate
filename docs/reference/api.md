# API 공통 규칙

> **작성 전입니다.** 아래 내용은 초안이며, 첫 API를 구현할 때 확정합니다.

모든 기능의 API가 따르는 규칙입니다. 기능별 엔드포인트는 각 기능 폴더의 `api.md`에 있습니다.
상세 스펙은 <Swagger/OpenAPI 주소, 도입 후 추가>에서 봅니다.

## 인증

- 1단계는 요청 헤더의 회원 ID를 믿는 간단한 인증을 씁니다. ([범위 밖](problem.md#범위-밖) 참고)
- <예: X-Member-Id: {memberId}>

## 멱등성

- 상태를 바꾸는 요청(POST, PATCH, DELETE)은 `Idempotency-Key` 헤더를 받습니다.
- 같은 키로 다시 요청하면 처리하지 않고 처음 결과를 그대로 반환합니다.
- 키 보관 기간: <예: 24시간>

## 에러 응답 형식

```json
{ "code": "COUPON_SOLD_OUT", "message": "쿠폰이 소진되었습니다" }
```

- `code`는 `<기능>_<상황>` 형식의 대문자 스네이크 케이스입니다. 예: `COUPON_SOLD_OUT`
- 클라이언트는 `message`가 아니라 `code`로 분기합니다.

## HTTP 상태 코드

| HTTP | 쓰는 경우 |
|---|---|
| 400 | 요청 형식 오류 |
| 401 | 인증 정보 없음 |
| 404 | 대상 없음 |
| 409 | 현재 상태 때문에 처리할 수 없음 (소진, 중복, 시작 전) |
| 503 | 일시적 실패. 다시 시도하면 성공할 수 있음 |
