# ADR (결정 기록)

되돌리기 어렵고, 다른 선택지와 비교해서 고른 결정만 씁니다. 예: 수량을 Redis로 관리할지 DB로 관리할지. 익숙한 도구를 고른 것처럼 비교가 없었던 결정은 쓰지 않습니다. 파일 이름은 `0001-<결정-요약>.md` 형식입니다.

| 번호 | 결정 | 상태 | 관련 Risk |
|---|---|---|---|
| [0001](0001-redis-decides-coupon-issue.md) | 쿠폰 발급은 Redis가 결정하고, DB는 기록만 한다 | 채택 | R1, R3, R4, R5 |
| [0002](0002-modular-monolith-with-one-port.md) | 모듈러 모놀리스로 만들고, 포트는 발급 전략 하나만 둔다 | 채택 | |

## 작성 형식

```markdown
# ADR-000N: <결정 제목>

- **상태**: 제안 / 채택 / 폐기 / ADR-000M으로 대체
- **날짜**: YYYY-MM-DD
- **관련 Risk**: R1

## 문제
## 선택지 (최소 2개, 장점·단점 표)
## 결정
## 이유 (실험 결과 링크)
## 감수하는 것
```
