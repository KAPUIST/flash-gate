# 주문 (order)

회원이 고른 상품을 쿠폰과 포인트를 적용해 주문하고, 취소하거나 구매 확정합니다.
재고·쿠폰·포인트는 한 트랜잭션에서 함께 차감하고, 취소할 때 함께 복구합니다.

| 항목 | 내용 |
|---|---|
| 만드는 순서 | 주문 ([문제 정의](../../reference/problem.md#만드는-순서)) |
| 코드 | `src/order/` (아직 없음) |
| 상태 | 설계 완료, 구현 전 |
| 소유 테이블 | [orders](../../reference/erd.md#orders-주문), [order_item](../../reference/erd.md#order_item-주문-상품), [order_coupon](../../reference/erd.md#order_coupon-주문에-쓴-쿠폰) |
| 다른 모듈을 거쳐 바꾸는 테이블 | [product_stock](../../reference/erd.md#product_stock-재고) (상품), [member_coupon](../../reference/erd.md#member_coupon-회원-쿠폰) (쿠폰), [member_point, point_history](../../reference/erd.md#member_point-point_history-포인트) (포인트), [cart_item](../../reference/erd.md#cart-cart_item-장바구니) (장바구니) |

## 공통 규칙

| 규칙 | 값 |
|---|---|
| 한 주문의 상품 수 | 1~20종 (가정) |
| 상품 하나의 수량 | 1~99개 |
| 같은 상품 | 한 주문에 한 줄. 같은 상품을 두 줄로 보내면 400 |
| 쿠폰 | 상품마다 상품 쿠폰 최대 1장, 주문마다 주문 쿠폰 최대 1장. 같은 회원 쿠폰은 두 번 쓰지 못합니다 |
| 포인트 | 5,000 이상일 때만 쓰고, 쿠폰 할인 뒤 금액의 10%와 잔액까지 씁니다. 이 규칙은 [포인트 모듈](../point/)의 `PointPolicy`가 가집니다 |
| 잠그는 순서 | 재고, 회원 쿠폰, 주문 저장, 포인트 잔액 순서. 재고는 상품 ID 오름차순, 회원 쿠폰은 ID 오름차순입니다. 취소는 주문 행을 먼저 바꾼 뒤 같은 순서를 씁니다 |
| 다른 모듈 | 재고·쿠폰·포인트·장바구니는 그 모듈이 공개한 서비스로만 바꾸고, 같은 트랜잭션에 참여합니다 ([ADR-0002](../../adr/0002-modular-monolith-with-one-port.md)) |

## 금액 계산 규칙

상품 쿠폰, 주문 쿠폰, 포인트 순서로 계산합니다. 주문서 보기·금액 미리 보기의 주문서와 주문하기는 같은 도메인 클래스로 이 순서대로 계산합니다.

1. 주문 상품 금액(줄 금액) = 단가 × 수량
2. 상품 쿠폰은 줄 금액에 적용하고, 줄 금액이 쿠폰의 최소 주문 금액 이상이어야 합니다. 할인은 줄 금액을 넘지 않습니다.
3. 상품 쿠폰 적용 후 합계 = 줄 금액 − 상품 쿠폰 할인의 합
4. 주문 쿠폰은 3의 합계에 적용하고, 3의 합계가 최소 주문 금액 이상이어야 합니다. 할인은 3의 합계를 넘지 않습니다.
5. 쿠폰 할인 뒤 금액 = 3의 합계 − 주문 쿠폰 할인
6. 포인트는 5,000 이상, 5의 10% 이하(원 미만 버림), 잔액 이하로 씁니다. 5의 10%가 5,000보다 작으면, 즉 쿠폰 할인 뒤 금액이 50,000원 미만이면 포인트를 쓸 수 없습니다.
7. 결제 금액 = 상품 금액 − 할인 합계 − 포인트

상품별로 나누기: 주문 쿠폰 할인과 포인트는 각 줄의 "상품 쿠폰 적용 후 금액" 비율로 나눕니다. 원 미만은 버리고, 남은 원 단위는 그 금액이 가장 큰 줄에 더합니다. 가장 큰 줄이 여럿이면 상품 ID가 가장 작은 줄에 더합니다. 지금은 전체 취소만 하지만, 나중에 부분 취소 때 돌려줄 금액의 근거가 됩니다.

금액 불일치를 막는 규칙: `orders`의 할인·포인트·결제 금액은 `order_item` 같은 컬럼의 합과 같아야 합니다. 테이블을 넘는 규칙이라 CHECK로는 못 겁니다. 그래서 주문 도메인 클래스가 만들 때 검사하고, 아래 예시를 테스트 데이터로 고정합니다.

### 계산 예시

회원의 포인트 잔액은 12,000입니다.

| 상품 | 브랜드 | 단가 | 수량 | 줄 금액 | 고른 상품 쿠폰 |
|---|---|---|---|---|---|
| A (ID 11) 러닝화 | 나이키 | 59,000 | 1 | 59,000 | 회원 쿠폰 101: 나이키 브랜드 쿠폰, 정률 10%, 최대 5,000원, 최소 30,000원 |
| B (ID 12) 양말 | 나이키 | 3,000 | 3 | 9,000 | 없음 |
| C (ID 13) 티셔츠 | 아디다스 | 25,000 | 2 | 50,000 | 회원 쿠폰 102: 상품 C 쿠폰, 정액 3,000원, 최소 20,000원 |

주문 쿠폰은 회원 쿠폰 103, 정액 10,000원, 최소 100,000원이고, 쓸 포인트는 7,000입니다.

1. 상품 쿠폰 할인은 A가 59,000 × 10% = 5,900이지만 최대 5,000이라 5,000이고, C는 3,000입니다.
2. 상품 쿠폰 적용 후 금액은 A 54,000, B 9,000, C 47,000이고, 합계는 110,000입니다.
3. 주문 쿠폰은 110,000 ≥ 100,000이라 쓸 수 있고, 할인은 10,000입니다.
4. 쿠폰 할인 뒤 금액은 100,000이고 포인트 한도는 10,000입니다. 7,000은 5,000 이상이고 한도와 잔액 이하라 쓸 수 있습니다.
5. 주문 쿠폰 10,000을 원 미만 버림으로 나누면 A는 10,000 × 54/110 = 4,909.09에서 4,909, B는 818.18에서 818, C는 4,272.72에서 4,272이고, 합은 9,999입니다. 남은 1원은 가장 큰 줄 A에 더해서 A가 4,910이 됩니다.
6. 포인트 7,000을 같은 방법으로 나누면 A는 3,436.36에서 3,436, B는 572.72에서 572, C는 2,990.90에서 2,990이고, 합은 6,998입니다. 남은 2원은 A에 더해서 A가 3,438이 됩니다.

## 시나리오 1. 주문서 보기

사전 조건: 로그인한 회원입니다.

1. 회원이 장바구니에서 상품을 골라 "주문하기"를 누르거나, 상품 상세에서 "바로 구매"를 누릅니다.
   - 장바구니에서 오면 장바구니 항목 ID 목록을 보내고, 수량은 장바구니에 담긴 수량입니다.
   - 바로 구매면 상품 ID와 수량을 보냅니다.
2. 주문서에 상품마다 지금 이름, 지금 가격, 줄 금액, 판매 상태(판매 중, 품절, 판매 중지)가 보입니다.
   - 장바구니 항목이 없거나 다른 회원의 것이면 404를 봅니다.
   - 삭제된 상품이 들어 있으면 "판매하지 않는 상품입니다"로 표시하고, 주문하기는 할 수 없습니다.
3. 상품마다 쓸 수 있는 상품 쿠폰 목록이 보입니다.
   - 회원의 회원 쿠폰 중 `ISSUED`이고 사용 기한이 지나지 않은 상품 쿠폰입니다.
   - 쿠폰 대상(상품 또는 브랜드)에 그 상품이 들어 있어야 합니다.
   - 줄 금액이 최소 주문 금액 이상이어야 합니다.
4. 쓸 수 있는 주문 쿠폰 목록이 보입니다. 최소 주문 금액은 상품 쿠폰을 적용하기 전 합계로 먼저 거르고, 고른 상품 쿠폰에 따라 다시 계산합니다([금액 미리 보기](#시나리오-2-쿠폰과-포인트를-골라-금액-미리-보기)).
5. 포인트 잔액과 쓸 수 있는 최대 포인트가 보입니다.
6. 아무것도 저장하지 않고, 재고와 쿠폰도 잡아 두지 않습니다.

#### 허용하는 지연·불일치

- 주문서의 가격과 재고는 보는 순간의 값이라 주문하기 전에 바뀔 수 있습니다. 바뀌면 주문하기에서 "금액이 바뀌었습니다"를 봅니다.

## 시나리오 2. 쿠폰과 포인트를 골라 금액 미리 보기

사전 조건: [주문서 보기](#시나리오-1-주문서-보기)의 주문서를 보고 있습니다.

1. 회원이 상품마다 상품 쿠폰을 하나씩, 주문 쿠폰을 하나 고르고 쓸 포인트를 입력합니다.
2. 서버가 [금액 계산 규칙](#금액-계산-규칙) 순서로 계산해 보여줍니다.
   - 상품별 상품 쿠폰 할인, 주문 쿠폰 할인, 포인트, 결제 금액
   - 상품별로 나눈 주문 쿠폰 할인과 포인트
3. 고른 쿠폰을 쓸 수 없으면 그 쿠폰 옆에 최소 주문 금액 미달, 사용 기한 지남, 대상 상품 아님 같은 이유를 보여줍니다. 계산에서는 그 쿠폰을 빼고 보여줍니다.
4. 포인트가 5,000 미만이거나 한도를 넘으면 "포인트는 5,000부터, 최대 N원까지 쓸 수 있습니다"를 보여줍니다. "최대 적용"을 고르면 한도와 잔액 중 작은 값을 씁니다.
5. 아무것도 저장하지 않습니다.

금액 불일치: 미리 보기와 주문하기는 같은 계산 클래스를 쓰고, 미리 보기에서도 주문 합계 = 상품별 합계를 검사합니다.

## 시나리오 3. 주문하기

사전 조건: [금액 미리 보기](#시나리오-2-쿠폰과-포인트를-골라-금액-미리-보기)에서 금액을 확인했습니다. 클라이언트는 주문서를 열 때 멱등 키를 하나 만들어 둡니다.

1. 회원이 "결제하기"를 누릅니다. 요청에는 상품(또는 장바구니 항목), 고른 쿠폰, 포인트, 화면에서 본 결제 금액, 멱등 키가 들어 있습니다.
2. 서버가 지금 가격으로 다시 계산합니다. 화면에서 본 결제 금액과 다르면 주문하지 않고 "금액이 바뀌었습니다. 다시 확인해 주세요"를 보여줍니다.
3. 한 트랜잭션에서 아래를 순서대로 하고, 하나라도 실패하면 전부 되돌립니다.
   1. 상품이 판매 중이고 삭제되지 않았는지 확인합니다. 아니면 "판매하지 않는 상품이 있습니다"를 봅니다.
   2. 재고를 상품 ID 오름차순으로 차감합니다. 한 상품이라도 재고가 모자라면 "품절된 상품이 있습니다"를 봅니다. (초과 판매, 주문 데드락)
   3. 고른 회원 쿠폰을 ID 오름차순으로 `USED`로 바꿉니다. 이미 썼거나 다른 회원의 쿠폰이면 "쓸 수 없는 쿠폰입니다"를 봅니다. 사용 기한, 대상, 최소 주문 금액은 도메인 클래스가 먼저 확인합니다. (쿠폰 이중 사용)
   4. 주문, 주문 상품, 주문에 쓴 쿠폰을 저장합니다. (금액 불일치)
   5. 포인트를 쓰면 잔액을 차감하고 사용 내역을 남깁니다. 내역에 주문 ID가 필요해서 주문을 저장한 뒤에 합니다. 잔액이 모자라면 "포인트가 부족합니다"를 봅니다. (포인트 이중 사용)
   6. 장바구니에서 왔으면 그 장바구니 항목을 지웁니다.
4. 주문이 완료되고 "주문이 완료되었습니다"와 주문 번호가 보입니다. 상태는 `ORDERED`입니다.

동시에 일어나는 일:

- 마지막 재고 1개에 주문 두 개가 동시에 오면 하나만 성공하고, 다른 하나는 품절을 봅니다. (초과 판매)
- 같은 회원이 같은 쿠폰으로 주문 두 개를 동시에 보내면 하나만 성공하고, 다른 하나는 "쓸 수 없는 쿠폰입니다"를 봅니다. (쿠폰 이중 사용)
- 상품 A, B를 담은 주문과 B, A를 담은 주문이 동시에 와도 둘 다 A, B라는 같은 순서로 잠가서 데드락이 나지 않습니다. (주문 데드락)

#### 허용하는 지연·불일치

- 재고·쿠폰·포인트·장바구니는 주문과 같은 트랜잭션에서 바뀌어서 어긋나는 순간이 없습니다.
- 상품 목록·상세에 보이는 재고와 품절 표시는 몇 초 늦을 수 있습니다. 실제로 주문할 수 있는지는 주문할 때 정해집니다.
- 주문 목록에는 주문 직후 바로 보입니다.

---

## 시나리오 4. 같은 주문을 두 번 보냄

사전 조건: [주문하기](#시나리오-3-주문하기) 요청을 보냈습니다.

1. 네트워크가 끊기거나 회원이 버튼을 두 번 눌러서, 같은 멱등 키로 요청이 한 번 더 옵니다.
2. 이미 그 키로 만든 주문이 있으면 새 주문을 만들지 않고 처음 주문을 그대로 보여줍니다. (중복 주문)
3. 두 요청이 동시에 오면 두 번째 요청은 첫 요청의 트랜잭션이 끝날 때까지 기다립니다. 첫 요청이 성공하면 두 번째는 처음 주문을 보여주고, 첫 요청이 실패하면 두 번째가 새로 처리됩니다.
4. 첫 요청이 품절 같은 이유로 실패했다면 아무것도 저장되지 않아서, 같은 키로 다시 보내면 새로 처리합니다.
5. 같은 키로 내용이 다른 요청을 보내도 요청 내용은 비교하지 않고 처음 주문을 보여줍니다. 클라이언트는 주문서를 열 때마다 새 키를 만듭니다 ([API 공통 규칙](../../reference/api.md#멱등성)).

---

## 시나리오 5. 내 주문 목록·상세 보기

사전 조건: 로그인한 회원입니다.

1. 회원이 "주문 내역"을 누르면 최근 주문부터 목록이 보입니다. 목록에는 주문 일시, 상태, 대표 상품 이름, 결제 금액이 나옵니다.
2. 주문을 누르면 상세가 보입니다. 상품마다 주문할 때의 이름·가격·수량, 상품 쿠폰 할인, 나눈 주문 쿠폰 할인과 포인트, 결제 금액이 보입니다. 쓴 쿠폰 목록도 보입니다.
3. 다른 회원의 주문이면 404를 봅니다.
4. 주문 내역은 주문 상품에 복사한 값만 읽어서, 상품 가격이 나중에 바뀌거나 상품이 삭제돼도 주문할 때의 값 그대로 보입니다.

---

## 시나리오 6. 주문 취소

사전 조건: 회원의 주문이 `ORDERED` 상태입니다.

1. 회원이 주문 상세에서 "주문 취소"를 누릅니다.
2. 한 트랜잭션에서 아래를 합니다.
   1. 주문을 `CANCELED`로 바꿉니다. 주문이 `ORDERED`가 아니면(이미 취소됐거나 구매 확정됐으면) "취소할 수 없는 주문입니다"를 봅니다.
   2. 재고를 상품 ID 오름차순으로 되돌립니다.
   3. 쓴 회원 쿠폰은 사용 기한이 지났어도 `ISSUED`로 되돌립니다. 만료는 계산으로 정하므로 기한이 지난 쿠폰을 다시 쓸 수는 없습니다.
   4. 쓴 포인트를 되돌리고 사용 취소 내역을 남깁니다.
3. 주문 상태가 "주문 취소"로 바뀐 것이 보입니다.

- 같은 주문을 동시에 두 번 취소하면 하나만 성공하고, 다른 하나는 "취소할 수 없는 주문입니다"를 봅니다.
- 취소와 구매 확정이 동시에 오면 먼저 커밋된 쪽만 성공합니다.
- 지금은 주문 전체 취소만 하고 부분 취소는 나중에 만듭니다. 필요한 금액은 이미 상품별로 기록돼 있습니다.

#### 허용하는 지연·불일치

- 없습니다. 주문·재고·쿠폰·포인트가 한 트랜잭션에서 바뀝니다.

---

## 시나리오 7. 구매 확정

사전 조건: 회원의 주문이 `ORDERED` 상태입니다.

1. 회원이 주문 상세에서 "구매 확정"을 누릅니다.
2. 주문을 `CONFIRMED`로 바꿉니다. 주문이 `ORDERED`가 아니면 "구매 확정할 수 없는 주문입니다"를 봅니다.
3. 결제 금액의 5%(원 미만 버림)만큼 포인트가 쌓이고, 결제 금액이 0원이면 쌓이지 않습니다. 예를 들어 결제 금액이 93,000원이면 4,650 포인트가 쌓입니다.
4. 확정된 주문은 취소할 수 없습니다.

- 결제를 붙이기 전에는 확정과 적립을 같은 트랜잭션에서 합니다.
- 결제를 붙인 뒤에는 확정만 하고, 적립은 비동기로 합니다 ([포인트 기능](../point/), [결제 기능](../payment/)).

#### 허용하는 지연·불일치

- 결제를 붙이기 전에는 없습니다.
- 결제를 붙인 뒤에는 확정 뒤 포인트가 몇 초 늦게 쌓일 수 있습니다.

---

## 시나리오 8. (시스템) 자동 구매 확정

사전 조건: 주문한 지 7일이 지났는데 `ORDERED` 상태인 주문이 있습니다 (7일은 가정).

1. 배치가 정해진 주기로 돕니다 (주기 1시간, 가정).
2. 대상 주문을 주문 ID 순서로 100건씩 읽습니다 (가정).
3. 주문마다 따로 트랜잭션을 열어 [구매 확정](#시나리오-7-구매-확정)과 같은 일을 합니다.
4. 그 사이 회원이 취소했거나 확정한 주문은 상태 조건에 걸려 바뀌지 않으므로 건너뜁니다.
5. 한 주문이 실패해도 다른 주문은 계속 처리하고, 실패한 주문은 다음 주기에 다시 대상이 됩니다.

#### 허용하는 지연·불일치

- 7일이 지난 주문이 배치 주기만큼 늦게 확정될 수 있습니다.
