# 장바구니 (cart)

회원이 주문하기 전에 상품을 담아 두고, 수량을 바꾸거나 뺍니다. 담아도 재고를 잡아 두지 않습니다.

| 항목 | 내용 |
|---|---|
| 단계 | 2단계 ([문제 정의](../../reference/problem.md#단계)) |
| 코드 | `src/cart/` (아직 없음) |
| 상태 | 설계 완료, 구현 전 |
| 관련 테이블 | `cart`, `cart_item` ([ERD](../../reference/erd.md#cart-cart_item-장바구니)). 읽기만: `product`, `product_stock`, `brand` |

## Risk

이 기능에는 Risk가 없습니다.

- 장바구니는 회원 한 명만 바꿉니다. 다른 회원과 경쟁하지 않습니다.
- 재고를 잡아 두지 않습니다. 재고 경쟁은 주문 기능의 `R6`입니다.
- 같은 회원의 동시 요청(처음 담기 두 번, 수량 합이 99를 넘는 담기)은 SQL 한 문장과 장바구니 행 잠금으로 막습니다 ([Flow](flows.md)).

## 장바구니 규칙

| 규칙 | 내용 |
|---|---|
| 장바구니 수 | 회원당 1개. 처음 담을 때 만든다 |
| 담을 수 있는 상품 | 판매 중, 품절. 판매 중지와 삭제된 상품은 담을 수 없다 |
| 상품당 수량 | 1~99개. 다시 담아서 합이 99를 넘으면 거절한다. 99로 줄여 담지 않는다 |
| 상품 종류 | 최대 100종 (가정). 넘으면 거절한다 |
| 가격 | 저장하지 않는다. 볼 때마다 지금 가격을 보여준다 |
| 빼기 | 행을 실제로 지운다 |
| 상품 삭제 | 관리자가 상품을 지우면, 그 상품의 장바구니 항목도 같은 트랜잭션에서 지운다 ([ERD](../../reference/erd.md#product-상품)) |
| 주문 | 주문한 상품은 주문 트랜잭션에서 장바구니에서 빠진다 ([주문](../order/)) |

다시 담아서 99를 넘을 때 99로 줄이지 않고 거절하는 이유: 회원이 담은 수와 실제 담긴 수가 말없이 달라지지 않게 하려는 것입니다.

## 시나리오 1. 장바구니에 담기

**사전 조건**: 로그인한 회원이다.

1. 회원이 상품 상세에서 수량을 고르고 장바구니 담기를 누른다.
2. 장바구니가 없으면 새로 만든다. 회원은 이 과정을 모른다.
3. 상품이 담기고 "장바구니에 담았습니다"가 보인다.
   - 이미 담긴 상품이면 새 줄이 생기지 않고 수량이 늘어난다. 예: 2개 담긴 상품을 3개 더 담으면 5개.
   - 품절 상품도 담긴다. 재고는 주문할 때 확인한다.
   - 늘어난 수량이 99를 넘으면 담기지 않는다. 회원은 "한 상품은 99개까지 담을 수 있습니다"를 본다 (`409 CART_QUANTITY_EXCEEDED`). 기존 수량은 그대로다.
   - 장바구니에 이미 100종이 있고 새 상품을 담으면 담기지 않는다. 회원은 "장바구니에는 100종까지 담을 수 있습니다"를 본다 (`409 CART_FULL`).
4. 판매 중지된 상품이면 담기지 않는다. 회원은 "판매 중이 아닌 상품입니다"를 본다 (`409 CART_PRODUCT_NOT_ON_SALE`).
5. 없는 상품이거나 삭제된 상품이면 "상품을 찾을 수 없습니다"를 본다 (`404 PRODUCT_NOT_FOUND`).
6. 수량이 1~99 밖이면 "요청 형식이 올바르지 않습니다"를 본다 (`400 COMMON_INVALID_REQUEST`).
7. 같은 회원이 처음 담기를 동시에 두 번 눌러도 장바구니는 하나만 생긴다. 두 요청의 수량은 모두 더해진다.

## 시나리오 2. 장바구니 보기

**사전 조건**: 로그인한 회원이다.

1. 회원이 장바구니를 연다.
2. 담은 상품이 최근 담은 순으로 보인다. 상품마다 이름, 브랜드, 지금 가격, 수량, 금액(지금 가격 × 수량), 판매 상태가 보인다.
   - 판매 상태는 상품 기능과 같은 규칙으로 계산한다: 판매 중, 품절, 판매 중지 ([상품 README](../product/README.md#판매-상태)).
   - 품절과 판매 중지 상품도 장바구니에 남아 보인다. 회원이 직접 뺄 수 있다.
3. 맨 아래에 합계가 보인다. 합계는 판매 중인 상품의 금액만 더한다.
4. 장바구니를 만든 적이 없거나 비어 있으면 빈 장바구니가 보인다. 에러가 아니다.

## 시나리오 3. 수량 바꾸기

**사전 조건**: 로그인한 회원이다. 장바구니에 상품이 있다.

1. 회원이 담긴 상품의 수량을 바꾼다.
2. 수량이 바뀌고 금액과 합계가 다시 계산된다.
   - 바꾸는 수량은 더하는 것이 아니라 새 수량이다. 예: 5개를 2로 바꾸면 2개.
   - 판매 중지·품절 상품도 수량을 바꿀 수 있다. 주문할 수 없을 뿐이다.
   - 같은 상품의 수량을 동시에 두 번 바꾸면 나중에 저장된 값이 남는다.
3. 수량이 1~99 밖이면 "요청 형식이 올바르지 않습니다"를 본다 (`400 COMMON_INVALID_REQUEST`). 0으로 만들려면 빼기를 쓴다.
4. 없는 장바구니 항목이거나 다른 회원의 항목이면 "장바구니 항목을 찾을 수 없습니다"를 본다 (`404 CART_ITEM_NOT_FOUND`).

## 시나리오 4. 빼기

**사전 조건**: 로그인한 회원이다.

1. 회원이 장바구니에서 상품 하나를 빼거나, 여러 개를 골라 한 번에 뺀다.
2. 고른 항목이 장바구니에서 사라진다. 합계가 다시 계산된다.
   - 이미 빠진 항목이나 없는 항목을 골라도 에러가 나지 않는다. 같은 요청을 두 번 보내도 결과가 같다.
   - 다른 회원의 항목 ID를 보내도 지워지지 않는다. 에러도 나지 않는다. 있다는 사실을 알려주지 않기 위해서다.
3. 한 번에 100개보다 많이 고르거나 아무것도 고르지 않으면 "요청 형식이 올바르지 않습니다"를 본다 (`400 COMMON_INVALID_REQUEST`).

**허용하는 지연·불일치** (모든 시나리오 공통)

- 장바구니의 가격과 판매 상태는 볼 때의 값이다. 주문할 때 다시 확인하고, 그때의 가격을 주문 상품에 복사한다.
- 판매 중으로 보였던 상품이 주문하는 순간 품절일 수 있다.
- 담은 수량이 남은 재고보다 많아도 장바구니에서는 알려주지 않는다. 주문할 때 품절로 처리한다.

## 공개 서비스 (다른 모듈이 부르는 것)

주문 모듈이 장바구니 모듈의 `index.ts`가 공개한 서비스를 함수로 부릅니다 ([모듈 사이의 규칙](../../reference/conventions.md#모듈-사이의-규칙)).
모든 메서드는 호출한 쪽의 트랜잭션에 참여합니다 (`@nestjs-cls/transactional`).

| 메서드 | 입력 | 하는 일 | 실패 |
|---|---|---|---|
| `getItems(memberId, cartItemIds)` | 회원 ID, 장바구니 항목 ID 목록 | 그 회원의 장바구니에 있는 항목의 상품 ID와 수량을 돌려준다 | 없거나 다른 회원의 항목이 하나라도 있으면 실패 (주문 모듈이 `404 ORDER_CART_ITEM_NOT_FOUND`로 응답) |
| `removeItems(memberId, cartItemIds)` | 회원 ID, 장바구니 항목 ID 목록 | `DELETE FROM cart_item WHERE id IN (...) AND cart_id = 회원의 장바구니`. 주문 트랜잭션 안에서 주문한 항목을 지운다 | |
| `removeItemsByProduct(productId)` | 상품 ID | 상품 삭제 트랜잭션 안에서 그 상품의 장바구니 항목을 모두 지운다 (관리자 기능, 범위 밖). 상품 모듈이 아니라 관리자 기능이 상품 삭제와 함께 부른다. 장바구니가 이미 상품을 부르므로, 상품이 장바구니를 부르면 모듈이 서로를 부르는 순환이 생긴다 | |
