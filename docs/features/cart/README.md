# 장바구니 (cart)

회원이 주문하기 전에 상품을 담아 두고, 수량을 바꾸거나 뺍니다. 담아도 재고를 잡아 두지 않습니다.

| 항목 | 내용 |
|---|---|
| 만드는 순서 | 주문 ([문제 정의](../../reference/problem.md#만드는-순서)) |
| 코드 | `src/cart/` (아직 없음) |
| 상태 | 설계 완료, 구현 전 |
| 관련 테이블 | `cart`, `cart_item` ([ERD](../../reference/erd.md#cart-cart_item-장바구니)). 읽기만: `product`, `product_stock`, `brand` |

## Risk

이 기능에는 Risk가 없습니다.

- 장바구니는 회원 한 명만 바꿔서 다른 회원과 경쟁하지 않습니다.
- 재고를 잡아 두지 않습니다. 재고 경쟁은 주문 기능의 초과 판매입니다.
- 같은 회원의 동시 요청은 SQL 한 문장과 장바구니 행 잠금으로 막습니다. 처음 담기를 두 번 하는 경우와 수량 합이 99를 넘는 담기가 여기에 해당합니다 ([Flow](flows.md)).

## 장바구니 규칙

| 규칙 | 내용 |
|---|---|
| 장바구니 수 | 회원당 1개. 처음 담을 때 만듭니다 |
| 담을 수 있는 상품 | 판매 중, 품절. 판매 중지와 삭제된 상품은 담을 수 없습니다 |
| 상품당 수량 | 1~99개. 다시 담아서 합이 99를 넘으면 99로 줄여 담지 않고 거절합니다 |
| 상품 종류 | 최대 100종 (가정). 넘으면 거절합니다 |
| 가격 | 저장하지 않고, 볼 때마다 지금 가격을 보여줍니다 |
| 빼기 | 행을 실제로 지웁니다 |
| 상품 삭제 | 관리자가 상품을 지우면 그 상품의 장바구니 항목도 같은 트랜잭션에서 지웁니다 ([ERD](../../reference/erd.md#product-상품)) |
| 주문 | 주문이 커밋되면 주문됨(`ORDER_PLACED`) 이벤트를 받아 주문한 상품을 장바구니에서 뺍니다 ([주문](../order/)). 이벤트를 잃으면 상품이 남고, 회원이 직접 지울 수 있습니다 |

회원이 담은 수와 실제 담긴 수가 말없이 달라지지 않도록, 다시 담아서 99를 넘으면 99로 줄이지 않고 거절합니다.

## 시나리오 1. 장바구니에 담기

사전 조건: 로그인한 회원입니다.

1. 회원이 상품 상세에서 수량을 고르고 장바구니 담기를 누릅니다.
2. 장바구니가 없으면 새로 만들고, 회원은 이 과정을 모릅니다.
3. 상품이 담기고 "장바구니에 담았습니다"가 보입니다.
   - 이미 담긴 상품이면 새 줄이 생기지 않고 수량이 늘어납니다. 예를 들어 2개 담긴 상품을 3개 더 담으면 5개가 됩니다.
   - 재고는 주문할 때 확인하므로 품절 상품도 담깁니다.
   - 늘어난 수량이 99를 넘으면 담기지 않고 "한 상품은 99개까지 담을 수 있습니다"가 보입니다 (`409 CART_QUANTITY_EXCEEDED`). 기존 수량은 그대로입니다.
   - 장바구니에 이미 100종이 있을 때 새 상품을 담으면 담기지 않고 "장바구니에는 100종까지 담을 수 있습니다"가 보입니다 (`409 CART_FULL`).
4. 판매 중지된 상품이면 담기지 않고 "판매 중이 아닌 상품입니다"가 보입니다 (`409 CART_PRODUCT_NOT_ON_SALE`).
5. 없는 상품이거나 삭제된 상품이면 "상품을 찾을 수 없습니다"가 보입니다 (`404 PRODUCT_NOT_FOUND`).
6. 수량이 1~99 밖이면 "요청 형식이 올바르지 않습니다"가 보입니다 (`400 COMMON_INVALID_REQUEST`).
7. 같은 회원이 처음 담기를 동시에 두 번 눌러도 장바구니는 하나만 생기고, 두 요청의 수량은 모두 더해집니다.

## 시나리오 2. 장바구니 보기

사전 조건: 로그인한 회원입니다.

1. 회원이 장바구니를 엽니다.
2. 담은 상품이 최근 담은 순으로 보입니다. 상품마다 이름, 브랜드, 지금 가격, 수량, 금액(지금 가격 × 수량), 판매 상태가 보입니다.
   - 판매 상태는 상품 기능과 같은 규칙으로 판매 중, 품절, 판매 중지 가운데 하나로 계산합니다 ([상품 README](../product/README.md#판매-상태)).
   - 품절과 판매 중지 상품도 장바구니에 남아 보이고, 회원이 직접 뺄 수 있습니다.
3. 맨 아래에 판매 중인 상품의 금액만 더한 합계가 보입니다.
4. 장바구니를 만든 적이 없거나 비어 있으면 에러가 아니라 빈 장바구니가 보입니다.

## 시나리오 3. 수량 바꾸기

사전 조건: 로그인한 회원이고, 장바구니에 상품이 있습니다.

1. 회원이 담긴 상품의 수량을 바꿉니다.
2. 수량이 바뀌고 금액과 합계가 다시 계산됩니다.
   - 바꾸는 수량은 더하는 값이 아니라 새 수량입니다. 예를 들어 5개를 2로 바꾸면 2개가 됩니다.
   - 판매 중지·품절 상품도 수량을 바꿀 수 있고, 주문만 할 수 없습니다.
   - 같은 상품의 수량을 동시에 두 번 바꾸면 나중에 저장된 값이 남습니다.
3. 수량이 1~99 밖이면 "요청 형식이 올바르지 않습니다"가 보입니다 (`400 COMMON_INVALID_REQUEST`). 0으로 만들려면 빼기를 씁니다.
4. 없는 장바구니 항목이거나 다른 회원의 항목이면 "장바구니 항목을 찾을 수 없습니다"가 보입니다 (`404 CART_ITEM_NOT_FOUND`).

## 시나리오 4. 빼기

사전 조건: 로그인한 회원입니다.

1. 회원이 장바구니에서 상품 하나를 빼거나, 여러 개를 골라 한 번에 뺍니다.
2. 고른 항목이 장바구니에서 사라지고 합계가 다시 계산됩니다.
   - 이미 빠진 항목이나 없는 항목을 골라도 에러가 나지 않습니다. 같은 요청을 두 번 보내도 결과가 같습니다.
   - 그 항목이 있다는 사실을 알려주지 않으려고, 다른 회원의 항목 ID를 보내면 지우지 않고 에러도 내지 않습니다.
3. 한 번에 100개보다 많이 고르거나 아무것도 고르지 않으면 "요청 형식이 올바르지 않습니다"가 보입니다 (`400 COMMON_INVALID_REQUEST`).

#### 허용하는 지연·불일치

모든 시나리오에 공통으로 적용합니다.

- 장바구니의 가격과 판매 상태는 볼 때의 값입니다. 주문할 때 다시 확인하고, 그때의 가격을 주문 상품에 복사합니다.
- 판매 중으로 보였던 상품이 주문하는 순간 품절일 수 있습니다.
- 담은 수량이 남은 재고보다 많아도 장바구니에서는 알려주지 않고, 주문할 때 품절로 처리합니다.

## 공개 서비스 (다른 모듈이 부르는 것)

주문 모듈이 장바구니 모듈의 `index.ts`가 공개한 서비스를 함수로 부릅니다 ([모듈 사이의 규칙](../../reference/conventions.md#모듈-사이의-규칙)).
모든 메서드는 호출한 쪽의 트랜잭션에 참여합니다 (`@nestjs-cls/transactional`).

| 메서드 | 입력 | 하는 일 | 실패 |
|---|---|---|---|
| `getItems(memberId, cartItemIds)` | 회원 ID, 장바구니 항목 ID 목록 | 그 회원의 장바구니에 있는 항목의 상품 ID와 수량을 돌려줍니다 | 없거나 다른 회원의 항목이 하나라도 있으면 실패 (주문 모듈이 `404 ORDER_CART_ITEM_NOT_FOUND`로 응답) |
| `removeItemsByProduct(productId)` | 상품 ID | 상품 삭제 트랜잭션 안에서 그 상품의 장바구니 항목을 모두 지웁니다 (관리자 기능, 범위 밖). 상품 모듈이 아니라 관리자 기능이 상품 삭제와 함께 부릅니다. 장바구니가 이미 상품을 부르므로 상품이 장바구니를 부르면 모듈이 서로를 부르는 순환이 생깁니다 | |

## 받는 이벤트

| 이벤트 | 하는 일 |
|---|---|
| 주문됨 (`ORDER_PLACED`) | `DELETE FROM cart_item WHERE id IN (이벤트의 cartItemIds) AND cart_id = 회원의 장바구니`. 이미 지운 항목이면 0행이 지워지고 그대로 끝납니다 |

- 주문 모듈은 장바구니를 지우라고 부르지 않고 이벤트만 보냅니다 ([모듈 사이 반응은 이벤트로](../../adr/0003-module-reactions-through-events.md)).
- 같은 이벤트를 두 번 받아도 지울 행이 없어서 결과가 같습니다.
