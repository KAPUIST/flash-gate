## Risk

Risk ID는 프로젝트 전체에서 이어서 매깁니다. 전체 결과는 [README 핵심 결과](../../../README.md#2-핵심-결과) 표에 모읍니다.

| ID | 깨지는 지점 | 시나리오 | 상태 | 근거 |
|---|---|---|---|---|
| R1 | 마지막 수량에 여러 명이 동시에 요청하면 한정 수량보다 많이 발급된다 | 1 | 미해결 | |
| R2 | 같은 회원이 짧은 시간에 여러 번 요청하면 한 회원에게 여러 장 발급된다 | 1 | 미해결 | |
| R3 | 수량은 줄었는데 발급 기록 저장에 실패하면 수량과 기록이 어긋난다 | 1 | 미해결 | |
| R4 | 요청이 몰리면 응답이 느려지거나 서버 에러가 난다 | 1 | 미해결 | |

상태 값: `미해결` → `재현함` (Before 수치 있음) → `해결` (After 수치 있음) / `보류`

## 시나리오 1. 행사 시작 직후 한정 수량 쿠폰 다운로드

**사전 조건**: 로그인한 회원이다. 쿠폰 발급 시작 시각이 지났다.

1. 회원이 행사 페이지에서 쿠폰 다운로드 버튼을 누른다.
2. 잔여 수량이 있으면 쿠폰이 발급되고 "쿠폰을 받았습니다"가 보인다.
   - 마지막 남은 수량에 여러 명이 동시에 누르면, 남은 수량만큼만 발급된다. 나머지는 "쿠폰이 소진되었습니다"를 본다. `R1`
   - 같은 회원이 짧은 시간에 여러 번 눌러도 한 장만 발급된다. 두 번째 요청부터는 "이미 받은 쿠폰입니다"를 본다. `R2`
   - 수량을 차감한 뒤 발급 기록 저장에 실패하면, 차감한 수량을 되돌리고 "다시 시도해 주세요"를 보여준다. `R3`
3. 잔여 수량이 없으면 쿠폰이 발급되지 않고 "쿠폰이 소진되었습니다"가 보인다.
4. 발급 시작 시각 전에 누르면 "아직 발급 시간이 아닙니다"가 보인다.

요청이 1분 동안 몰려도 위 응답이 목표 시간 안에 와야 한다. `R4`

**허용하는 지연·불일치**

- 화면에 보이는 잔여 수량은 몇 초 늦게 반영될 수 있다.
- 실제 발급 기록 수는 어떤 순간에도 한정 수량을 넘으면 안 된다.
- 회원이 받은 쿠폰 목록에는 발급 직후 1초 안에 보여야 한다 (목표, 미검증).
