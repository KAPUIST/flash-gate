# 실험 기록

Risk마다 최소 한 번 깨뜨리고, 고치고, 다시 잽니다. 파일 이름은 `E01-<실험-요약>.md` 형식입니다.

| 번호 | 실험 | 관련 Risk | Before → After |
|---|---|---|---|
| - | 아직 없음 | | |

## 실험 계획

아직 하나도 하지 않았습니다. 번호는 실험을 실제로 할 때 붙이고, 아래는 순서만 정한 계획입니다.

| 순서 | 실험 | 관련 Risk | 비교할 구현 | 볼 숫자 | 단계 |
|---|---|---|---|---|---|
| 1 | 로컬 기준선 | 전체 | 빈 응답, DB 조회 1번, Redis 명령 1번 | 최대 RPS, p99. 이후 실험의 천장 | 1 |
| 2 | 쿠폰 초과 발급 재현과 해결 | R1 | DB `findOne` → `save` (Before) / DB 조건부 UPDATE / Redis SADD + INCR | 회원 쿠폰 수 − 한정 수량 | 1 |
| 3 | 쿠폰 발급 응답 시간 | R4 | DB 조건부 UPDATE / Redis SADD + INCR ([ADR-0001](../adr/0001-redis-decides-coupon-issue.md) 검증) | 3,000 RPS에서 p99, 5xx 수 | 1 |
| 4 | 중간 실패와 Redis 재시작 | R3, R5 | 저장 직전 서버 종료, Redis 재시작 후 복구 있음·없음 | Redis 수 − 회원 쿠폰 수, 초과 발급 수 | 1 |
| 5 | Lua로 명령 묶기 | R3, R4 | SADD + INCR 두 번 / Lua 한 번 | 처리량, 어긋남 수. 참고 사례의 "Lua 약 21% 느림" 확인 | 1 |
| 6 | 재고 초과 판매 | R6 | `findOne` → `save` (Before) / 조건부 UPDATE / 비관적 락 / 낙관적 락 + 재시도 / Redis | 판매 수량 − 처음 재고, p99, 재시도 수 | 2 |
| 7 | 여러 상품 주문 데드락 | R8 | 상품 순서 그대로 잠금 (Before) / 상품 ID 순서로 잠금 | 데드락 에러 수 | 2 |
| 8 | 쿠폰 이중 사용 | R7 | 읽고 나서 UPDATE (Before) / 조건부 UPDATE | 취소되지 않은 주문 두 개에 쓰인 회원 쿠폰 수 | 2 |
| 9 | 같은 멱등 키 동시 요청 | R10 | 키 확인 후 INSERT (Before) / UNIQUE 제약 | 같은 키의 주문 수 | 2 |
| 10 | 포인트 동시 사용 | R11 | 읽고 나서 UPDATE (Before) / 조건부 UPDATE | 잔액 < 0 시도 수, 잔액 = 내역 합 여부 | 2 |
| 11 | 포인트 적립 메시지 중복 | R12 | UNIQUE 없음 (Before) / `UNIQUE(order_id, type)` | 주문당 적립 내역 수 | 3 |
| 12 | 결제 장애 주입 | R13, R14 | Mock PG 거절·지연·응답 없음 | 결제 승인됐는데 주문이 끝나지 않은 건수 | 3 |

`R2`(중복 요청이 409로 끝남)와 `R9`(금액 불일치)는 부하 실험이 아니라 동시성 테스트와 단위 테스트로 증명합니다.

## 작성 형식

```markdown
# E0N: <실험 제목>

- **날짜**: YYYY-MM-DD
- **관련 Risk**: R1
- **관련 ADR**: ADR-000N

## 가설
## 환경 (머신, 인프라, 데이터, 도구, 스크립트)
## 1차 측정 (Before)
## 원인 (로그, 쿼리, 그래프 근거)
## 개선 (커밋·PR 링크)
## 2차 측정 (Before / After 표)
## 결론과 남은 문제
```
